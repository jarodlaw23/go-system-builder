# 修复

1. 确认实际行为、期望行为、受影响的版本或情境。使用现有复现、日志和测试找出失败路径。复现不可用时，说明可观察证据与仍待确认的条件。
2. 沿实际调用定位原因，检查同一原因影响的入口、数据和兼容约定。修改必要部分。保留未受影响的行为，避免顺带改变契约或掩盖错误。
3. 按风险验证原复现和受影响的边界。优先使用现有可执行检查，只有现有检查无法捕捉明确回归时才补定向用例。
4. 交付原因、改动、实跑命令与结果，以及仍待验证的场景。在同一 Issue 或计划中更新可接手的信息。
