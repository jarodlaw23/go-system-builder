# 开发

1. 读需求、确认的原型和相关实现，写清用户动作、预期结果和必要边界。小任务沿用 Issue 或会话中的验收清单。需要跨模块决定或交接时，使用 [实施计划](../../../templates/implementation-plan.md)。
2. 复用项目现有页面、接口、数据定义和测试入口。按可验收的行为拆分工作。确认被改动的界面动作、调用、权限、数据写入和反馈串起来，保留现有错误和兼容行为。需要变更公共契约时更新其权威定义。
3. 用与改动相称的项目检查验证验收项。涉及跨层行为时检查实际调用边界。根据风险覆盖失败、空值、旧数据或重试。描述使用了真实依赖还是替身，并记录未执行的检查。
4. 更新同一任务的结果。说明交付内容、版本、实际验证和剩余事项。
